# TODO List — фронтенд (Лаба 0)

Простая страница TODO: форма для добавления задачи + список задач.
Ходит в бэкенд по HTTP; если бэкенд не задан — работает на mock-данных
в памяти (без сохранения в cookies/localStorage).

Часть Лабы 0 «свой сервис». Дальше сервис переиспользуется: nginx перед
фронтом, упаковка в Docker, сборка в CI/CD.

![Скриншот приложения](docs/screenshot.png)

## Возможности

- Добавить задачу через форму (`POST /task`).
- Получить список задач (`GET /tasks`).
- Индикатор режима в шапке: `mock` или `backend`.
- Изменение/удаление задач пока не предусмотрено.

## Контракты API

Бэкенд должен реализовывать:

```
POST /task
Body:
{
  "task": { "title": "string" }
}
```

```
GET /tasks
Response:
{
  "tasks": [ { "title": "string" } ]
}
```

`Task = { "title": "string" }`.

## Стек

Vite + vanilla JS. Без фреймворка, сборка — статические файлы (удобно
класть за nginx и в Docker).

## Запуск

Нужен Node.js 18+.

1. Установить зависимости:

```bash
npm install
```

2. Настроить `.env` (скопировать из примера):

```bash
cp .env.example .env
```

- `VITE_BACKEND_URL` **пусто** → mock-режим (данные в памяти).
- `VITE_BACKEND_URL=http://localhost:8000` → ходит в реальный бэкенд.

3. Dev-режим (с hot-reload):

```bash
npm run dev
```

Открыть http://localhost:5173

4. Прод-сборка (статика в `dist/`, дальше отдаётся nginx):

```bash
npm run build
npm run preview   # локальный предпросмотр сборки на http://localhost:4173
```

## Проверка работоспособности

1. Открыть страницу.
2. Ввести текст в форму, нажать «Добавить».
3. Задача появляется в списке.

> В mock-режиме данные живут только до перезагрузки (это ожидаемо: реального
> хранилища нет). Полная проверка «сохранил → перезагрузил → запись на месте»
> заработает после подключения бэкенда с базой (Лаба 1) через `VITE_BACKEND_URL`.
